## Safety note

Nothing in this repository executes an attack. Rules are YAML text, and the "attack logs" are
JSON lines describing process-creation events. All hosts use the reserved `.test` domain, all URLs
use `example.com` / `example.net`, and the encoded PowerShell in the fixtures decodes to
`Write-Output 'hello'`.

## What the benign logs test

Each benign file holds near misses written to break a lazy rule: the same binary doing
something normal (`certutil -hashfile`, `vssadmin list shadows`, `schtasks /query`), a similar
string in another program (`notepad ... -enc.txt`), or an allow-listed parent (a Google updater
creating a task in AppData).

## Known limits (next milestones)

- Fixtures are hand-written events that reproduce the command lines of the referenced Atomic
  Red Team tests. M2 replaces or extends them with recorded OTRF Security-Datasets logs and runs
  them through Elastic in Docker.
- A 3-to-4-event sample proves the logic, not a false-positive rate. Tracking that rate on real
  telemetry is an M3 goal.

## Dependency audit (added 2026-10-04)

The first CI run failed `make audit`: `pip-audit` reported diskcache 5.6.3 (PYSEC-2026-2447,
CVE-2025-69872, GHSA-w8v5-vhqr-4h9v). DiskCache loads cached values with pickle, so someone who can
write to the cache folder can run code when the cache is read. No fixed release exists yet.

| Question | Answer |
|---|---|
| Who depends on it? | pySigma, only in `sigma.data.mitre_attack` (an optional ATT&CK data cache under `~/.cache/pysigma`) |
| Does this project load it? | No: `test_vulnerable_diskcache_is_never_loaded` parses every rule with pySigma and evaluates every rule in a fresh interpreter, then asserts neither `diskcache` nor `sigma.data.mitre_attack` was imported |
| Decision | `make audit` ignores exactly these three IDs, with the reason in the Makefile; every other finding still fails CI. Remove the exception when diskcache ships a fix or pySigma drops it. |
