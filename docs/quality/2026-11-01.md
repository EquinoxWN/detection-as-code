## Defects fixed

| Where | Defect | Fix and test |
|---|---|---|
| `sigma.py` `_atom` | `1 of them` and patterns like `1 of *` also included `_`-prefixed selections. The Sigma specification and pySigma exclude them unless the pattern itself starts with `_`, so a rule with a `_filter` helper could fire on events pySigma would not. | Same rule as pySigma. `test_them_and_patterns_skip_underscore_selections`, plus a `1 of them` case that now fails loudly when only `_` selections exist. |
| `sigma.py` `_selection_predicate` | An empty selection (`sel: {}`) matched every event (`all([])` is true); pySigma rejects it ("Detection is empty"). | Raises `UnsupportedSigmaError`. New case in `test_unsupported_features_fail_loudly`. |
| `sigma.py` `_field_predicate` | A nested map as a field value was compared as its Python `str()`; pySigma rejects it ("Unsupported type"). | Raises `UnsupportedSigmaError`. New case in `test_unsupported_features_fail_loudly`. |
| `rules.py` `metadata_problems` | `owner:` left blank in YAML loads as `None`, and `str(None)` is `"None"`, so a rule without an owner passed the policy. | Owner must be a non-blank string. `test_metadata_policy_rejects` (owner `None`). |
| `rules.py` `metadata_problems` | `tags` given as a string or with a number crashed with `TypeError`; `detection` given as a list was not reported clearly. | Reported as policy problems. Three cases in `test_metadata_policy_rejects`. |
| `rules.py` `load_rule`, `_read_jsonl` | An empty rule file crashed with `TypeError`; a fixture line that is valid JSON but not an object crashed later with `AttributeError`; invalid JSON gave no file or line. | Clear `ValueError` with file (and line). `test_rule_file_must_be_a_mapping`, `test_jsonl_reports_bad_lines`. |

## Known limitations

- The local evaluator implements a strict subset of Sigma (see the `sigma.py` docstring); anything
  else fails loudly instead of matching wrong. Checking the same rules in a real SIEM is M2.
- Fixtures are hand-written events, so the benign sample proves the logic, not a false-positive
  rate (unchanged from M1, see `docs/results/m1.md`).
